# 私有云端求职进度板设计

日期：2026-09-02

## 1. 目标与范围

将现有的单文件本地求职进度板升级为仅供一人使用的云端网页。用户通过邮箱验证码登录，可在电脑、手机和不同浏览器中查看并更新同一份投递与面试数据。

本版本包含：

- 邮箱验证码登录，仅预先创建的个人账号可登录；
- 投递记录、面试复盘和状态时间线的云端存储；
- 同一公司的多个岗位自动归组；
- 云端同步、搜索、筛选、统计和 JSON 备份；
- 响应式电脑及手机界面。

本版本不包含团队协作、公开注册、邀请、共享链接、多人权限、离线编辑和旧数据迁移。

## 2. 技术方案

### 2.1 前端与托管

- 使用 Vite 构建轻量前端，延续现有 HTML/CSS/JavaScript 界面和交互。
- 使用 `@supabase/supabase-js` 处理登录、数据库读写及会话。
- 使用 Vercel 托管构建后的静态网页，提供固定 HTTPS 地址。
- Supabase 项目地址和公开匿名密钥使用 Vercel 环境变量注入。公开匿名密钥只能调用受行级安全策略允许的操作，不具备后台管理权限。

### 2.2 登录

- Supabase Auth 中预先创建唯一允许登录的用户账号。
- 登录页接收邮箱并发送六位验证码；调用时设置 `shouldCreateUser: false`，禁止从网页创建新账号。
- 验证码正确后建立浏览器会话；会话由 Supabase SDK 安全持久化和刷新。
- 数据库行级安全策略同时校验登录用户 ID；即使有人绕过前端，也无法读取或修改该用户的数据。
- Supabase 后台关闭公开用户注册。退出登录后清除当前会话并返回登录页。

## 3. 数据模型

### 3.1 `applications`：投递记录

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | UUID | 主键 |
| `user_id` | UUID | 所属登录账号 |
| `company` | TEXT | 公司显示名称 |
| `company_key` | TEXT | 用于归组的标准化公司名称 |
| `role` | TEXT | 岗位名称 |
| `location` | TEXT | 工作地点 |
| `channel` | TEXT | 投递渠道 |
| `applied_date` | DATE | 投递日期 |
| `status` | TEXT | 当前状态 |
| `next_action` | TEXT | 下一步行动 |
| `next_date` | DATE | 下一步日期 |
| `salary` | TEXT | 薪资范围 |
| `contact` | TEXT | 联系人信息 |
| `job_url` | TEXT | 职位链接 |
| `tags` | TEXT[] | 标签列表 |
| `notes` | TEXT | 备注 |
| `created_at` | TIMESTAMPTZ | 创建时间 |
| `updated_at` | TIMESTAMPTZ | 最近更新时间 |

`company_key` 由前端在保存时生成：去除首尾空格、合并连续空格并转为小写。该规则能将 `Tencent`、`tencent` 和带多余空格的写法归为一组，但不会自动合并“腾讯”和“Tencent”，以避免错误判断。

### 3.2 `interviews`：面试问题与复盘

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | UUID | 主键 |
| `application_id` | UUID | 关联投递，删除投递时级联删除 |
| `user_id` | UUID | 所属登录账号 |
| `date` | DATE | 面试日期 |
| `stage` | TEXT | 面试轮次 |
| `rating` | SMALLINT | 0–5 自评分数 |
| `questions` | TEXT | 面试问题 |
| `highlights` | TEXT | 回答与亮点 |
| `gaps` | TEXT | 卡点与不足 |
| `next_plan` | TEXT | 下一步改进 |
| `feedback` | TEXT | 结果或面试官反馈 |
| `created_at` | TIMESTAMPTZ | 创建时间 |
| `updated_at` | TIMESTAMPTZ | 最近更新时间 |

新增或修改面试记录时，数据库触发器同步刷新对应投递的 `updated_at`，使该岗位和公司组自动移动到最新位置。

### 3.3 `status_history`：状态时间线

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | BIGINT | 主键 |
| `application_id` | UUID | 关联投递，删除投递时级联删除 |
| `user_id` | UUID | 所属登录账号 |
| `status` | TEXT | 变更后的状态 |
| `changed_at` | TIMESTAMPTZ | 变更时间 |

数据库触发器在新增投递及状态变化时自动写入时间线，避免前端遗漏历史记录。

## 4. 同公司归组与排序

前端获取当前用户的全部投递后，以 `company_key` 归组：

1. 每个公司的组更新时间等于组内所有岗位最大的 `updated_at`；
2. 公司组之间按组更新时间从新到旧排列；
3. 同一公司内部的岗位按 `updated_at` 从新到旧排列；
4. 更新投递字段、投递状态或关联面试复盘都会刷新相关岗位的 `updated_at`；
5. 搜索和状态筛选先作用于岗位，再保留有匹配岗位的公司组。

页面以公司标题行加岗位子行展示。同一公司只有一个岗位时仍使用相同结构，保持排序逻辑一致。公司标题显示公司名、岗位数量和该公司最近更新时间。

## 5. 页面与交互

### 5.1 登录页

- 第一步输入邮箱并发送验证码；
- 第二步输入六位验证码完成登录；
- 支持重新发送、修改邮箱和清晰的错误提示；
- 不提供注册入口。

### 5.2 主页面

- 顶部继续显示全部投递、面试中、已获录用和七天内待跟进数量；
- “投递记录”使用同公司归组视图；
- “面试问题与复盘”继续按面试日期显示卡片，并关联公司和岗位；
- 新增、编辑和删除操作成功后重新读取云端数据；
- 页面顶部显示“正在同步”“已同步”或“同步失败”的轻量状态提示；
- 保留搜索、状态筛选、排序和响应式手机布局。

### 5.3 备份

- “导出备份”从云端读取当前账号的投递、面试和时间线并生成 JSON；
- 因用户选择从云端直接开始录入，本版本不提供旧本地数据迁移和 JSON 导入，避免错误覆盖云端数据。

## 6. 安全与数据权限

- 三张业务表全部启用 Supabase Row Level Security；
- 查询、新增、修改和删除策略均要求 `auth.uid() = user_id`；
- `user_id` 默认取当前登录用户，前端不能替其他用户写入数据；
- 面试和状态记录还需关联属于同一用户的投递；
- Vercel 仅保存 Supabase URL 和公开匿名密钥；`service_role` 管理密钥绝不进入前端或代码仓库；
- 职位备注、联系人和面试复盘不写入浏览器日志或分析服务。

## 7. 数据流与错误处理

1. 页面启动后恢复登录会话；无会话时显示登录页。
2. 登录成功后并行读取投递、面试和状态时间线。
3. 页面在内存中计算统计、归组和排序，不复制或修改数据库原始数据。
4. 保存操作期间禁用重复提交；成功后重新加载受影响的数据。
5. 网络失败时保留表单内容并显示重试提示，不将未确认成功的修改显示为已同步。
6. 删除投递前二次确认，并提示关联面试记录将被级联删除。
7. 会话过期时回到登录页，不继续发起写操作。

## 8. 测试与验收

### 8.1 自动测试

- 公司名称标准化：大小写、首尾空格和连续空格；
- 归组排序：公司组按最大更新时间排序、组内岗位按更新时间排序；
- 搜索和状态筛选后的归组结果；
- 状态统计和七天内待跟进计算；
- 表单字段与数据库字段之间的转换。

### 8.2 集成与安全验证

- 邮箱验证码登录、退出和会话恢复；
- 投递、面试及状态历史的新增、读取、修改和删除；
- 修改面试复盘后，对应岗位和公司组移动到最新位置；
- 未登录请求被拒绝；非所属用户无法查询或修改数据；
- 删除投递时关联面试和状态历史被级联删除。

### 8.3 页面验收

- 桌面和手机尺寸下均可完成登录、投递维护和面试复盘；
- 同一公司的两个或更多岗位始终连续显示；
- 保存后刷新网页或更换设备登录，数据保持一致；
- 网络异常、验证码错误和删除操作均有明确反馈。

## 9. 部署与首次配置

1. 创建 Supabase 项目并执行随项目提供的数据库初始化 SQL；
2. 在 Supabase Auth 中创建唯一用户并关闭公开注册；
3. 将验证码邮件模板配置为显示六位 OTP；
4. 在 Vercel 中配置 Supabase URL 和公开匿名密钥；
5. 部署站点，通过指定邮箱完成首次登录；
6. 完成安全验证后开始正式录入数据。
